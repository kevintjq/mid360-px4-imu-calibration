# Mid360 / PX4 IMU 外参标定

[English](README.md) · 中文

ROS1 / Ubuntu 20.04 C++ 工具。读取 FAST-LIO `/Odometry` 和 MAVROS `/mavros/imu/data`，引导你完成桌面静止、拿起、手持三轴往复和放下验证，批量估计旋转、杆臂与加速度组合偏置。程序不向飞控发布数据。

## 快速开始

```bash
sudo apt install ros-noetic-roscpp ros-noetic-roslib ros-noetic-sensor-msgs \
  ros-noetic-nav-msgs libeigen3-dev
mkdir -p ~/catkin_ws/src
cd ~/catkin_ws/src
git clone https://github.com/kevintjq/mid360-px4-imu-calibration.git
cd ~/catkin_ws
catkin_make -DCMAKE_BUILD_TYPE=Release
source devel/setup.bash
roslaunch mid360_px4_calibration online_calibration.launch
```

已有仓库时，在仓库目录运行 `git pull --ff-only`，再回到工作空间重新编译。先启动 MAVROS 和 FAST-LIO；建议把标定节点单独放在一个终端，避免其他节点日志穿插。

输入要求：

- 设备刚性连接，FAST-LIO 持续正常跟踪；odom 的位置单位为米。
- IMU 提供有效的 ENU 姿态、FLU 机体系角速度（rad/s）与包含重力的加速度计比力（m/s²）。
- 两路时间戳递增、时钟同步。无效或乱序帧会被丢弃；坐标系变化、断流或超时会停止采集。
- **支持 200 Hz 里程计**，与 IMU 不必同频。高频不会缩短每轴的最低采集时间；重复发布旧位姿不会增加有效信息。

## 跟着终端完成八步

默认全程自动切换，无需按键。飞机只需在开始时放稳、初始化后拿起、三轴结束后放下，**轴与轴之间保持手持，不用反复放回桌面**。

| 步骤 | 终端提示与操作 | 默认条件 |
| --- | --- | --- |
| 01 / 08 连接数据源 | 启动 MAVROS、FAST-LIO，飞机先放稳 | 等待有效话题，最多 30 秒 |
| 02 / 08 桌面静止初始化 | 桌面或地面放稳，松手不动 | 连续静止 8 秒，至少 100 帧 IMU |
| 03 / 08 拿起飞机 | 拿起，离开原位置约 10 cm 以上，然后手持停稳 | 准备至少 5 秒；odom 确认位移至少 8 cm 并持续 0.5 秒 |
| 04 / 08 横滚 ROLL | 手持居中停稳后，绕机体前后轴左右倾斜约 ±20–35°，缓慢往复 | 居中静止 2 秒；运动阶段至少 20 秒 |
| 05 / 08 俯仰 PITCH | 继续手持居中停稳，再绕机体左右轴前后俯仰约 ±20–35° | 居中静止 2 秒；运动阶段至少 20 秒 |
| 06 / 08 偏航 YAW | 继续手持居中停稳，尽量保持水平，左右转向约 ±30–45° | 居中静止 2 秒；运动阶段至少 20 秒 |
| 07 / 08 放下与验证 | 轻放回稳定平面，松手，等待晃动停止 | 先留出 5 秒放置缓冲，再完整静止 5 秒 |
| 08 / 08 求解与验收 | 等待质量检查，按提示查看结果或失败原因 | 全部质量门限通过后才保存 |

**拿起阶段不会仅凭倒计时结束。** 如果一直放在桌面上，程序会等待你实际移开飞机；最多等待 120 秒。这里检查的是相对初始位置的距离，不要求 FAST-LIO 世界系是 ENU，也不判断桌面接触或绝对高度。拿起、放下与各次准备阶段均不加入三轴求解窗口。

### 运动怎样才算达标

每次往复约 **3–5 秒**，自然加速、减速，通常每轴往复 3–5 次，未达标就继续平滑往复。不要猛甩、连续转圈或大幅平移。每轴必须同时满足：

| 条件 | 默认目标 |
| --- | --- |
| 采集时长 | 至少 20 秒 |
| 有效运动时长 | 至少 8 秒 |
| 正向 / 反向累计转角 | 每个方向至少 1.5 rad，约 86° |
| IMU / odom 样本 | 至少 300 / 80 帧 |
| 里程计整体转动量 | 至少 1.8 rad，约 103°，用于确认 odom 确实有旋转 |

转角是多次往复的累加，**不用一次倾斜 86°**。安装方向未知时，不要求两路数据的同名轴一起变化。默认三轴运动至少 60 秒，完整流程通常约 1.5–3 分钟；每轴最多等待 180 秒。

静止检查使用逐样本角速度、RMS、角速度/加速度波动、数据连续性与两路姿态变化。相对静止参考的姿态变化超过默认 1°，或检测到运动、加速度突变、缺帧时，会清空候选窗口；从后续合格样本重新采满完整时长。缓慢转动、往复转动或短暂晃动都不能靠平均抵消绕过检查。

## 终端显示

UTF-8 交互终端显示统一卡片：当前步骤、当前动作、总进度、逐项实测值与目标值。`✓` 绿色表示达标，`○` 黄色表示尚未达标，底部直接列出还差哪些条件。验收失败项使用红色 `✗`，并附具体原因。

✓ 采集时长    20.0 / 20.0 s

宽度自动适配，中文按显示宽度对齐。终端足够高时原地刷新；终端较小、`TERM=dumb` 或重定向输出时改为定期日志，阶段切换立即输出。普通重定向日志不含控制码；设置 `NO_COLOR=1` 可关闭颜色，仍保留可用的原地刷新。动态面板不是完整原始数据记录。

## 输出与坐标系

默认文件：

- `~/.ros/mid360_px4_calibration/result.yaml`
- `~/.ros/mid360_px4_calibration/result.txt`

输出定义为 `p_B = R_B_M * p_M + t_B_M`：`M` 是 FAST-LIO body，必须确认原点和轴对应 Mid360 IMU；`B` 是 MAVROS 提供的 PX4 FLU 参考机体系。`t_B_M` 是 Mid360 原点相对 PX4 参考原点的位置，表达在 FLU 中。用于硬件安装偏移前，应核对参考原点与目标配置一致。

FAST-LIO 世界系（通常 `camera_init`）不必是 ENU。程序将世界系位置求导后转回 body。输出的 ENU 平移只是固定 FLU 杆臂在 `enu_reference_stamp` 的表达，不是固定世界系外参。

YAML/TXT 包含旋转矩阵、四元数 `[x,y,z,w]`、固定 FLU 平移、参考时刻的 ENU 平移、偏置、时间补偿约定、质量指标/阈值和采集区间。新增 `solver_model: matched_integral_v1` 标识积分一致性求解模型。旋转使用矩阵和四元数，替代旧 `rpy_mid360_to_body_XYZ_deg` 字段；保留 `translation_body_FLU_m` 平移别名。

支持 `~/`、绝对路径和相对包目录的输出路径，父目录自动创建。验收失败不覆盖已有结果；文件写入检查成功后逐个重命名。两个文件不构成跨文件原子事务，部分保存失败会报错并返回非零。退出码：`0` 为验收且保存成功，`2` 为配置/采集/保存失败，`3` 为求解或质量验收失败。

## 参数与质量验收

完整配置见 [online_calibration.yaml](config/online_calibration.yaml)。自定义配置可用：

```bash
roslaunch mid360_px4_calibration online_calibration.launch config:=/绝对路径/custom.yaml
```

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `pickup_min_duration_s` | 5 | 拿起准备的最短时长（秒） |
| `pickup_min_displacement_m` | 0.08 | 拿起阶段相对原位的位移门限（米） |
| `pickup_timeout_s` | 120 | 拿起阶段超时（秒） |
| `putdown_buffer_s` | 5 | 最终静止窗口前的放置缓冲（秒） |
| `axis_min_duration_s` / `axis_min_active_s` | 20 / 8 | 每轴最低采集 / 有效运动时间（秒） |
| `axis_direction_target_rad` | 1.5 | 每个方向累计转角目标 |
| `static_max_rotation_deg` | 1 | 静止候选窗口允许的姿态变化（度） |
| `imu_time_offset_s` | 0 | 对齐 IMU 时间 = 原始 IMU 时间 + 此值 |
| `max_gyro_rmse_rad_s` | 0.12 | 角速度向量 RMSE 上限 |
| `max_gyro_relative_rmse` / `min_gyro_correlation` | 0.25 / 0.95 | 相对误差上限 / 运动一致性下限 |
| `max_accel_rmse_m_s2` | 0.75 | 加速度向量 RMSE 上限 |
| `min_rotation_excitation_ratio` | 0.02 | 三轴旋转激励比下限 |
| `max_translation_condition` | 1000 | 消去偏置后杆臂系统的条件数上限 |
| `min_translation_excitation_rad_s2` | 0.03 | 最弱方向绝对激励下限 |
| `min_angular_accel_rms_rad_s2` | 0.1 | 角加速度 RMS 下限 |
| `max_lever_arm_m` | 2 | 安装杆臂物理长度上限 |

当前求解模型为 **同窗口积分一致性匹配**，默认半窗口仍为 0.3 秒：

1. **旋转**：比较里程计窗口两端的相对旋转与去偏陀螺仪在同一窗口内的旋转积分，再做 SVD 配准。角速度 RMSE、相对误差与一致性指标均由同窗口的旋转向量除以时长计算，表示窗口平均运动的一致性。
2. **杆臂**：对位置和旋转矩阵使用同一个离散二阶算子，并通过其配套积分核处理重力补偿后的 IMU 加速度。两侧具有相同的时间响应，消除平滑求导与瞬时加速度混用造成的系统偏差。局部旋转对数求导仅用于运动筛选和角加速度诊断，不再直接构造杆臂方程。
3. **偏置与退化**：联合估计杆臂和常量机体系加速度组合偏置；先投影消去随姿态变化的积分偏置基，再检查杆臂系统条件数和最弱方向激励。
4. **时间与数据**：积分区间必须在有效 IMU 范围内，不能跨阶段或长缺帧；积分核归一性也会检查。FAST-LIO 世界系无需是 ENU。不使用经常为零的 odom twist。

求解阶段包含逐窗积分，采集结束后请等待终端验收结果。
相对角速度误差为 `RMSE / sqrt((IMU_RMS² + odom_RMS²) / 2)`。运动一致性为旋转对齐后配对向量的归一化点积总和，不减均值，不是 Pearson 系数。绝对误差、相对误差、一致性及其他质量项必须同时通过；终端箭头 `↑ / ↓` 表示门限方向。

**程序不自动估计时间偏移。** 先保证驱动时钟同步，仅在已知偏移时设置补偿。误差过大时先查时间、单位、跟踪和刚性安装。通过默认门限不等于获得了某种绝对精度，建议重复采集并与尺量安装尺寸对照。

## 验证与常见情况

核心测试不依赖 ROS：

```bash
cd ~/catkin_ws/src/mid360-px4-imu-calibration
c++ -std=c++14 -O1 -Iinclude -I/usr/include/eigen3 \
  tests/calibration_math_test.cpp -o /tmp/calibration_math_test
/tmp/calibration_math_test
```

也可在启用测试的 `catkin_make` 构建后，进入 `~/catkin_ws/build` 执行 `ctest --output-on-failure -R calibration_math_test`。测试覆盖已知外参恢复、偏置退化、静止重计时、姿态变化、相对误差、拿起确认，以及 10/20/50/200 Hz 的无噪声和多种随机噪声三轴轨迹；另测多轴同时转动、不均匀采样、实际量级的 epoch 时间戳、非 ENU 世界系、IMU 缺帧和时间不重叠。无噪声轨迹的杆臂误差门限为 0.1 mm，固定带噪轨迹为 2 mm，替代原来的 2 cm 宽容差。

以下为同一组 200 Hz odom / 100 Hz IMU 合成轨迹的对比；带噪样例使用固定种子 42：

| 数据 | 旧求解杆臂误差 | 当前求解杆臂误差 |
| --- | ---: | ---: |
| 无噪声 | 12.44 mm | 约 0.016 mm |
| 固定噪声 | 12.72 mm | 约 0.29 mm |

噪声设置为位置各轴 0.5 mm、姿态绕 X 轴 0.2 mrad、角速度各轴 0.003 rad/s、加速度各轴 0.02 m/s² 的独立高斯噪声。上述数值是特定合成轨迹的结果，不代表实机精度；同步误差、相关里程计漂移、实际姿态误差和刚性安装仍会影响结果。

| 现象 | 先检查 |
| --- | --- |
| 等待数据源超时 | 两个话题是否更新、IMU 姿态是否有效、时间戳是否同步 |
| 拿起阶段不前进 | 是否实际离开原位、odom 位置是否正常更新 |
| 手持准备反复重计时 | 回到中间姿态短暂停稳，检查振动与姿态漂移 |
| 运动进度停住 | 看面板底部“尚需达标”；时间、两个方向、样本和 odom 转动都要满足 |
| 质量验收失败 | 按红色失败项排查，保留原结果；不要只放宽门限 |
| 输出无法保存 | 检查输出目录权限与剩余空间 |

数值测试、模拟流程与终端检查不能替代真实 ROS Noetic/catkin 编译和实机验证；本项目尚未完成后两项验证。
